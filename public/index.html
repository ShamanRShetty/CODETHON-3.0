Robust Security Architecture

Forward-Proof File Protection

Engineered according to zero-trust principles so that even if a link leaks, your file remains uncompromised.

Envelope AES-256-GCM

Every file is encrypted with its own unique random 256-bit key. The data key is wrapped by the Master Key and ciphertext is safely stored with authenticated tags.

Identity OTP Verification

Recipients must prove identity via a 6-digit email OTP (HMAC-SHA256). Strangers requesting access are blocked and logged without revealing recipient lists.

Strict Access Checker Door

Every request passes through an immutable 6-stage validation pipeline: Token → Revocation → Expiry → Download Limits → Recipient OTP → Password.

Self-Destruct & Download Limits

Set max downloads (e.g., burn after 1 read) and time expiration. The moment the limit is reached, access is permanently sealed.

1-Click Instant Revocation

Sent a file by mistake? Revoke the share instantly from your dashboard. Active links immediately return 404 with no traces revealed.

Real-Time Audit Trail

Every download, wrong password, expired attempt, or stranger intrusion is logged with timestamp, visitor IP, and user-agent.

Zero-Trust Lifecycle

How VaultLink Secures Every File

From upload to download, plaintext data never exists unencrypted.

01

Key Generation

Node crypto generates a cryptographically secure 256-bit random key and 96-bit IV.

02

AES-256-GCM

File is encrypted into ciphertext. Authentication tag is calculated to prevent bit-flipping.

03

Key Wrapping

File key is wrapped using the server MASTER_KEY. Ephemeral file key is wiped from RAM immediately.

04

Verified Delivery

Recipient passes OTP + Access Checker; file is decrypted in-flight and streamed with strict headers.

Frequently Asked Questions

Everything you need to know about VaultLink's security architecture.

What happens if an unauthorized person gets my link?

They cannot download the file. When they enter their email, the system checks the allowed recipient list. Since they are not listed, no OTP is sent, their attempt is blocked, and their intrusion attempt (with IP and timestamp) is logged in your audit trail.

Are raw share tokens stored in the database?

No. Only the SHA-256 hash of the 32-byte cryptographically random token is stored in the database. Raw tokens are displayed once to the creator and never saved in plaintext.

Can recipients execute malicious scripts inside the browser?

No. VaultLink enforces mandatory download security headers (Content-Disposition: attachment, X-Content-Type-Options: nosniff, and Cache-Control: no-store). Files are never rendered inline in the browser.

How does link revocation work?

When you revoke a share, its timestamp is set instantly in SQLite. Any subsequent access attempts immediately fail the Access Checker, logging the attempt as REVOKED and returning a generic 404 to the visitor.
